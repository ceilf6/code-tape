老师们、同学们好，我们做的是 code-tape，一个基于 Web 技术的代码讲解录制与回放平台。



PRD 里对这个项目的定义很明确：录制者在内置代码编辑器里写代码时，系统要同步采集语音、摄像头、键盘输入、鼠标轨迹、文本选区等操作行为，最后生成一个可交互回放的讲解内容。



所以它和传统录屏的区别是：传统录屏只能看到画面，而 code-tape 记录的是结构化的代码讲解过程。观看者回放时不仅能看视频，还能看到代码如何变化、鼠标指向哪里、触发过什么快捷键、运行结果什么时候出现。



接下来我用一个很小的 HTML + CSS + JS 页面，演示 PRD 里 P0 主流程从录制到回放的完整闭环。

```javascript
function changeText(){
  const title = document.getElementById('title')

  if(title.innerHTML === 'hello'){

    title.innerHTML = 'hello'
  }
}
```

下面用一段带攻击性的测试代码，展示前端沙箱的安全处理。

```javascript
document.body.innerHTML = "<h1>Sandbox OK</h1>";

try {
  parent.document.body.dataset.sandboxEscaped = "yes";
  console.log("parent write unexpectedly succeeded");
} catch (e) {
  console.error("parent DOM blocked:", e.name);
}

try {
  localStorage.setItem("x", "1");
} catch (e) {
  console.error("storage blocked:", e.name);
}

try {
  await fetch("/");
  console.log("fetch unexpectedly worked");
} catch (e) {
  console.error("network blocked:", e.name);
}

alert("弹窗应该被拦截");
console.log("sandbox still alive");
```

这段代码会尝试做几件危险的事：改父页面 DOM、写 localStorage、发起网络请求、弹窗。

如果没有隔离，这些行为可能污染 code-tape 自己的页面。现在它们会被 sandbox 边界拦截，用户代码只能影响预览 iframe 内部，不能逃逸到主应用。

这些都得归功于 CSP 安全内容策略与 iframe 的配合



同时咱们的 UI 也有进行优化，例如图标的处理、主题色的切换，都是走一个简洁大气的路线

最后咱们看一下 AI 字幕生成功能

这个功能分为两个阶段，首先会调用 ASR 模型进行音频转文字，然后会根据 ASR 模型的结果调用大模型进行纠错和章节生成

这里咱们支持配置外部厂商去进行请求，假如没有配置的话，ASR 模型就会以开源的作为兜底，从 huggingface 上拉取模型，由于模型比较大所以可能时间较长，所以这个模型会提前预热，在组件挂载时就会加载；而大模型的话用的是通过 gpt-5.5 蒸馏结合咱们场景适配的训练语料进行微调得到的 ONNX 模型
