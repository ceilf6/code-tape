# code-tape 训练营分享演示脚本

> 适用场景：训练营/评委现场分享。
>
> 推荐时长：正式演示 6 到 8 分钟，最长不超过 10 分钟。
>
> 核心记忆点：code-tape 不是传统录屏，而是把代码讲解过程记录成可定位、可恢复、可交互的结构化时间线。

## 一、演示目标

本次分享要让评委快速看懂三件事：

1. **产品价值**：代码讲解不应该只是视频，观看者需要看到代码是如何一步步产生的。
2. **核心链路**：录制者可以边写代码边讲解，系统同步记录代码、鼠标、选区、快捷键、运行结果和音视频，最终生成可回放内容。
3. **技术亮点**：事件流优先、快照 seek、iframe sandbox、媒体同步，让回放既可交互又稳定。

不要把分享讲成纯架构课。面向评委时，先让他们看到产品可用，再解释背后的技术判断。

## 三、演示代码

现场建议使用 JavaScript，稳定性最好，代码量也适合短时间演示。

### 1. 初始输入

先输入函数签名和注释，边写边讲：

```js
/**
 * Return the indexes of two numbers whose sum equals target.
 */
function twoSum(nums, target) {
}
```

### 2. 第一阶段：讲思路

继续输入：

```js
/**
 * Return the indexes of two numbers whose sum equals target.
 */
function twoSum(nums, target) {
  const seen = new Map();

  for (let i = 0; i < nums.length; i += 1) {
    const current = nums[i];
    const need = target - current;
  }
}
```

这时用鼠标指向 `need` 这一行，讲：

> 这里的关键是不要双重循环。我们每次只看当前数字 `current`，然后计算它还需要哪个数字 `need` 才能凑成目标值。

### 3. 第二阶段：完成核心逻辑

继续输入：

```js
/**
 * Return the indexes of two numbers whose sum equals target.
 */
function twoSum(nums, target) {
  const seen = new Map();

  for (let i = 0; i < nums.length; i += 1) {
    const current = nums[i];
    const need = target - current;

    if (seen.has(need)) {
      return [seen.get(need), i];
    }

    seen.set(current, i);
  }

  return [];
}
```

讲解：

> 如果 `need` 已经在 map 里，说明之前某个位置的数字和当前数字正好组成答案。否则就把当前数字和下标记录下来，留给后面的数字匹配。

### 4. 第三阶段：添加运行用例

继续输入：

```js
/**
 * Return the indexes of two numbers whose sum equals target.
 */
function twoSum(nums, target) {
  const seen = new Map();

  for (let i = 0; i < nums.length; i += 1) {
    const current = nums[i];
    const need = target - current;

    if (seen.has(need)) {
      return [seen.get(need), i];
    }

    seen.set(current, i);
  }

  return [];
}

console.log(twoSum([2, 7, 11, 15], 9));
console.log(twoSum([3, 2, 4], 6));
```

预期输出：

```text
[0, 1]
[1, 2]
```

### 5. 快捷键演示

任选一个稳定快捷键：

- 格式化代码：`Shift + Option + F` 或项目页面支持的格式化入口。
- 注释一行：`Cmd + /`。
- 撤销/恢复：`Cmd + Z` 后再 `Shift + Cmd + Z`。

推荐使用 `Cmd + /` 注释一行，因为观众能明显看到代码变化。

操作方式：

1. 选中 `return [];` 这一行。
2. 按 `Cmd + /`。
3. 等快捷键 Badge 出现后，再按一次 `Cmd + /` 恢复。

讲解：

> 普通输入会通过内容变更事件记录，而像注释、撤销、格式化这类控制型动作，会单独记录为快捷键事件。回放时右下角会短暂展示快捷键 Badge，观看者能知道讲解者当时做了什么操作。

## 四、逐分钟演示脚本

- 页面停在 code-tape 首页或录制页。
- 不急着点按钮，先讲一句产品定位。

讲稿：

> 大家好，我们做的是 code-tape，一个代码讲解录制与回放工具。它解决的问题是：传统录屏只能看画面，但代码讲解更关心的是代码怎么一步步写出来、讲解者指向了哪里、用了什么快捷键、运行结果是什么时候出现的。所以我们没有做纯视频录制，而是把这些操作记录成一条结构化时间线。

### 0:30 - 1:10 产品价值

屏幕操作：

- 简单展示录制工作台布局：编辑器、运行预览、控制条、摄像头预览。
- 鼠标扫过主要区域即可，不要打开太多菜单。

讲稿：

> 这个工具适合算法讲解、代码 Review、面试复盘和编程教学。比如讲 Two Sum，观看者不只是看到最终代码，而是可以回到任意时间点，看当时编辑器里的代码、鼠标指向、选区、快捷键和运行结果。这是它和普通录屏最大的区别。

### 1:10 - 1:40 开始录制

### 1:40 - 2:30 输入函数骨架

- 输入第一段函数签名和空函数。
- 输入时速度放慢，不要一次性粘贴全部代码。

输入代码：

> 我先写一个 Two Sum 的函数。这个题目的目标是返回两个数字的下标，它们的和等于 target。

### 2:30 - 3:20 输入 map 解法思路

屏幕操作：

- 补充 `seen`、循环、`current`、`need`。
- 鼠标指向 `need` 这一行，停 1 到 2 秒。

输入代码：


讲稿：

### 3:20 - 4:10 完成核心逻辑

屏幕操作：

2. 暂停。

### 7:20 - 8:20 技术亮点

屏幕操作：

- 停在回放页面，不切到 IDE 或终端。
- 鼠标指向进度条、编辑器、运行结果区域，辅助解释。

讲稿：

> 技术上我们围绕“事件流优先，音视频辅助”设计。录制时，编辑器内容变化、光标选区、鼠标轨迹、快捷键和运行结果都会进入事件流；音视频是同步轨道，但不是代码事实源。
>
> seek 的难点是不能每次都从头重放，所以我们使用快照加增量事件。跳到某个时间点时，先找到最近的快照，再静默应用后续事件，这样可以快速恢复编辑器稳定状态。
>
> 代码运行采用 iframe sandbox。这样既能展示前端运行结果，又避免用户代码污染主页面。回放时默认展示录制当时的运行结果，而不是重新执行历史代码，保证一致性。

>
> 工程上，PRD 是最高权威，技术方案明确了 P0/P1/P1+ 的边界。核心模块有单元测试，录制回放链路有 E2E，并通过 GitHub Actions、GitNexus 和 repo-guard 做质量检查。

讲稿：

## 六、现场风险与兜底话术

### 1. 摄像头或麦克风权限失败

操作：

- 不要反复刷新。
- 直接选择无音视频录制，或切换备用回放。

话术：

> 音视频是辅助轨道，不影响核心事件流。即使没有摄像头或麦克风，代码、鼠标、选区、快捷键和运行结果仍然可以被完整录制和回放。

### 2. 运行预览失败

操作：

- 检查是否少了括号或逗号。
- 如果仍异常，保留错误结果并继续。

话术：

> 运行失败本身也是讲解过程的一部分。系统会把 stdout、stderr 或 error 记录下来，回放时也能看到当时的运行状态。

### 3. 保存失败或 IndexedDB 异常

操作：

- 使用备用录制包。
- 如页面提供导出能力，选择导出文件。

话术：

> P0 的设计里，本地保存是主路径，文件导出是兜底路径。即使存储失败，也要保证事件流不丢失。

### 4. seek 不稳定

操作：

- 不要在同一个位置连续拖动多次。
- 改用预先准备好的备用回放展示 seek。

话术：

> seek 是回放引擎最核心也最难的部分。我们的设计是通过最近快照加增量事件恢复状态，目标是在任意时间点快速回到稳定编辑器状态。

### 5. 云端或分享链接不稳定

操作：

- 不现场排查网络。
- 回到本地回放中心。

话术：

> 云端回放和分享是 P1 产品化能力，核心录制回放闭环不依赖云端。本地录制包本身已经包含完整事实源。
